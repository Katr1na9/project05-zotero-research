# Network Forensics Method Based on Evidence Graph and Vulnerability Reasoning

## 1. 基本信息

- 中文译名：基于证据图与漏洞推理的网络取证方法
- 作者：Jingsha He; Chengyue Chang; Peng He; Muhammad Salman Pathan
- 年份：2016
- Venue：Future Internet, 8(4), 54
- DOI：https://doi.org/10.3390/fi8040054
- 开放全文：https://www.mdpi.com/1999-5903/8/4/54
- 阅读日期：2026-07-14
- 阅读优先级：必读（历史直接先例）
- 所属主题：Network Forensics / PCAP + Logs / Evidence Graph / Attack Reconstruction

## 2. 一句话总结

本文将网络包与网络程序日志标准化为带 `Data_Source` 的事件向量，构建可回溯原始证据的有向证据图，再结合主机漏洞分数推断攻击节点与路线；它证明“包 + 日志 + 证据图 + 攻击场景重构”早在 2016 年已有明确先例，但其双源关系仍是规则式确定连接，缺少双线独立建模、跨源边校准、冲突传播和现代链级评价。

## 3. 研究问题

- 单一网络包或 IDS 告警为何容易形成不完整、误导性的取证证据？
- 如何把网络包和异构程序日志转换为统一表示并构建证据图？
- 如何结合网络拓扑与漏洞信息，从证据图恢复多阶段攻击路线并定位攻击者/受害者？
- 如何把推理结果回指到原始网络包，满足取证可追溯性？

## 4. 核心贡献

1. 提出包含采集、预处理、标准化、图构建、证据推理和呈现的模块化网络取证框架。
2. 定义事件向量 `EV=<ID, Source, Target, Operation, Timestamp, Data_Source>`，统一网络包和日志记录。
3. 构建边带时间、操作和数据来源属性的有向证据图，并保留回查原始证据的路径。
4. 提出 Vulnerability Evidence Reasoning Algorithm（VERA），基于 Nodeworth、Linkworth 和漏洞分数识别关键节点与攻击路线。
5. 在自建场景及 DARPA LLDOS 1.0/2.0.2 上进行案例验证，并与 Wang 的图方法作定性比较。

## 5. 方法框架

### 输入

- 网络包：论文将其视为主要证据，经 SVM 过滤出可疑包。
- 网络程序日志：包括 Web 应用等日志，被视为辅助证据。
- 网络拓扑、NVD/CVE/CVSS 与 Nessus 漏洞扫描结果。

### 输出

- 由主机/对象节点和带时间、动作、来源属性的边构成的 Evidence Graph。
- 攻击者、受害者、关键节点、攻击路线和多阶段攻击场景。
- 可由图节点/路径回查的原始数字证据。

### 关键模块

| 模块 | 作用 | 可借鉴点 |
|---|---|---|
| Event Vector | 统一包与日志的公共字段 | 证明跨源中间表示和来源字段是历史基础要求 |
| SVM 过滤 | 从大规模包中筛选可疑流量 | 可作为流量侧候选事件生成的旧基线 |
| Evidence Graph | 按实体、动作和时间组织证据 | 图构建本身可成为贡献，但必须细化边语义和来源锚点 |
| VERA | 结合漏洞分数排序攻击节点和路径 | 可作为确定性/启发式攻击路径基线 |

### 方法流程

```text
网络包 + 程序日志 + 漏洞数据
  -> 采集、数字签名/时间戳与预处理
  -> Event Vector 标准化
  -> 可疑包 SVM 过滤
  -> Evidence Graph 构建
  -> VERA 漏洞证据推理
  -> 攻击者、受害者、攻击路线与原始证据回查
```

## 6. 数据集与实验

- SVM 训练使用 DARPA/KDD-CUP-99 式 41 维连接特征：训练 7,312 条、测试 6,980 条，RBF 核，567 个支持向量；论文只给出 ROC 图和参数，未提供完整分类混淆矩阵。
- 自建环境包括 Windows/Linux 目标机、流量生成器、Snort 和多种模拟攻击；规模较小，主要用于案例展示。
- 外部数据采用 MIT Lincoln Laboratory LLDOS 1.0 与 LLDOS 2.0.2。
- 作者展示的最终图能够复原端口/服务探测、Sadmind 利用、提权、后门安装和 DDoS 等步骤，并称与官方场景一致。
- 与 Wang 方法的比较主要基于图的完整性和案例观察，没有边级、路径级 Precision/Recall/F1，也没有统计显著性与跨场景泛化评价。

## 7. 关键知识点

- “网络包 + 程序日志 -> 统一事件表示 -> 证据图”不是新的任务组合。
- `Data_Source` 只标明证据来自包或日志，并不等于保留 packet frame number、log record ID、文件哈希、解析器版本等不可变原始锚点。
- 论文将网络包设为主要来源、日志设为辅助来源，尚未研究两条证据线的独立贡献、互补增益和冲突。
- 图边由公共实体、动作和时间等确定性规则形成，没有候选边集合、后验概率、拒绝状态和校准指标。
- VERA 中漏洞分数用于排序潜在攻击/受害节点，不能等同于从观测证据学习出的因果概率。

### 术语翻译

| 英文 | 建议译法 | 备注 |
|---|---|---|
| Evidence Graph | 证据图 | 图边代表可呈现、可推理的取证关系 |
| Event Vector | 事件向量 | 跨包/日志的统一事件中间表示 |
| Vulnerability Evidence Reasoning | 漏洞证据推理 | 将漏洞分数引入路径与节点排序 |

## 8. 优点

- 很早就明确指出单一来源证据可能不完整或误导，并联合网络包与日志。
- 统一表示中显式保留 `Data_Source`，具备基本证据来源意识。
- 将图构建、攻击路线恢复和原始证据回查放在同一取证流程内。
- 使用两套公开 LLDOS 场景展示多阶段攻击重构，而非只做单点入侵检测。

## 9. 局限

- 数据和攻击场景陈旧、规模小，无法代表当代加密流量、云原生、NAT、并发 campaign 与跨域网络。
- 日志解析与双源对齐机制描述粗略，日志在主要实验中的实际独立贡献不清楚。
- EV 对象粒度较粗，未给出不可变原始记录锚点、完整性证明和 append-only 证据束。
- 无跨源边真值、校准、缺失源/冲突源实验，也没有模态消融。
- 图中“关系”主要由规则构造，不能直接主张因果。
- VERA 的 Nodeworth/Linkworth 强依赖预先扫描的漏洞分数，面对零日漏洞和配置漂移较弱。
- 攻击链只做案例层面比较，缺乏边级、路径级、阶段级和结论忠实度指标。

## 10. 对我选题的启发

- 不能声称“首次把 PCAP 与日志构建成证据图”或“首次用双源图重构攻击链”。
- 可守住的图谱贡献应是：流量线和日志线各自形成有来源锚点的观察子图，再对跨源候选关系进行学习/校准，并显式保留冲突、拒绝和不确定状态。
- Project03 的 `ThreatObservation` 可升级为流量侧 schema；日志侧必须有对等的 `LogObservation`，而不是把日志当附属字段。
- 现代实验必须分别报告 traffic-only、log-only、简单拼接、确定性 EV 图和校准双源图，证明两条线各自及联合的边际贡献。
- LLM 应在冻结的证据子图上提出链/意图候选并回引 packet/log 锚点，而不是替代图边验证。

## 11. 可转化的研究问题

1. 相比统一 EV 后直接连边，保留双线子图并校准跨源关系能否降低共享 IP、时钟漂移和 NAT 导致的错误合并？
2. 流量侧与日志侧各自贡献哪些链步骤，两者联合后在哪些攻击阶段产生互补增益？
3. 带原始锚点和冲突状态的证据图能否提升 LLM 攻击链/意图结论的可验证性与拒答质量？

## 13. 论文写作可引用句式

- 早期网络取证研究已经将网络包与程序日志统一为带来源字段的事件向量，并借助证据图和漏洞推理恢复多阶段攻击路线；因此，现代工作的增量不能停留在多源建图本身，而应落实到来源保持、跨源关联可靠性和可量化的链级证据质量。

## 14. 我的批注与疑问

- 论文结论建议数字签名和时间戳，但正文没有给出完整 chain-of-custody 实现与实验。
- 网络包是“primary”、日志是“accessorial”，这与本支线的双线对等贡献假设不同，正好构成可检验的改进点。
- SVM 输入是 41 维连接记录而非逐帧原始包语义；后续对比时要区分 raw PCAP、flow feature 和 packet anchor。
- 作者关于“更完整”的结论以图示和官方叙事一致性为主，不能视为现代 benchmark 上的定量优势。
