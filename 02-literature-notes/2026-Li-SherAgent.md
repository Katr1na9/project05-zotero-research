# SherAgent: Evidence-Grounded Agentic Backtracking for Security Alert Investigation

## 1. 基本信息

- 中文译名：SherAgent：面向安全告警调查的证据约束智能体回溯
- 作者：Zhenyuan Li; Zhengkai Wang; Ling Jiang; Xiangmin Shen; Ruixiao Lin; Sen Nie; Shi Wu; Shouling Ji
- 年份：2026
- 来源：arXiv 预印本
- arXiv：https://arxiv.org/abs/2607.09176
- 阅读状态：`full-read`
- 阅读日期：2026-07-14
- 所属主题：Agentic Investigation / Provenance Backtracking / Missing Logs / SOC

## 2. 一句话总结

SherAgent 在生产 SOC 日志库上由 LLM 迭代生成结构化查询、放宽检索条件、过滤分支并回溯告警来源，能够在 provenance chain 不完整时提出潜在关联并给出固定类别结论；它直接占据“智能体处理缺失事件并回溯攻击链”的方向，但没有独立原始流量图、跨源边校准、高层意图真值或公开可复现实验资产。

## 3. 研究问题

- 生产日志经常存在缺失、字段不完整和链路断裂，传统确定性回溯为何频繁失败？
- LLM 能否根据当前证据动态生成下一步数据库查询，而非依赖固定规则？
- 如何控制回溯分支数量、避免无关事件造成 token 与分析成本失控？
- 如何在证据不足时输出可审计的终止结论，而非强行生成完整攻击故事？

## 4. 核心贡献

1. 将告警调查建模为面向结构化日志数据库的迭代查询、分支过滤和 provenance 回溯。
2. 当严格查询无结果时，按预设策略逐步放宽字段条件，恢复断裂的事件链。
3. 根据命令行、路径、账户、网络端点等语义字段过滤候选分支，并维护 `Used/Tracing/New` 树状态。
4. 允许加入 `potential correlation` 边连接证据不完整的事件，同时进行全局树审计。
5. 设计五类固定终止结果，并在大规模生产告警、专项断链集和用户研究中评价系统。

## 5. 方法框架

### 输入

- 告警事件及其关联的 process、file、network 日志。
- ClickHouse 中按事件类型分表保存的生产日志。
- SQL 查询模板、查询放宽规则和终止类别。

### 输出

- 以告警为起点的回溯树、保留分支与潜在关联。
- 攻击入口或不可调查原因等固定类别结论。

### 关键模块

| 模块 | 作用 | 对本支线的边界意义 |
|---|---|---|
| Iterative query generation | LLM 决定下一步结构化日志查询 | 可作联合图查询智能体 baseline |
| Query relaxation | 无结果时逐级放宽条件 | 已占据 missing-log 自适应检索 |
| Semantic branch pruning | 过滤大量无关回溯分支 | 可降低 LLM 上下文与分析成本 |
| Global tree audit | 检查整棵树并决定继续或终止 | 与 evidence sufficiency/abstention 相关 |

### 方法流程

```text
安全告警 -> 查询模板与 LLM 生成 SQL -> 日志库检索
       -> 无结果则逐级放宽 -> 分支语义过滤
       -> 回溯树状态更新 -> 全局审计
       -> 继续调查 / 固定类别终止
```

## 6. 数据集与实验

- 生产部署使用 DeepSeek V3.1 和 ClickHouse，处理 53,849 个真实告警；先对 10,000 个告警做经验分析。
- 重点评测集包括 125 个断链但可调查样本、25 个对抗性不可调查样本和 50 个完整链样本；三名 SOC 分析员多数投票标注。
- 论文表 3 报告 SherAgent 成功率 92.2%、无效率 7.8%、结论一致性 88.5%；基线分别为 61.1%、38.9%、66.5%。成功率定义为可调查案例中是否找到正确入口，不是链边 F1。
- 对 broken link/entity/attribute 三类缺失，恢复成功率分别为 93.9%、78.3%、88.9%。
- 分支排序 Top-1 命中率 95.4%；一个示例中 136 条分支仅保留 14 条。
- 最佳配置平均约 379k tokens、0.10 美元、185 秒；基线约 560k tokens、0.16 美元、393 秒。
- 对 53,849 个线上告警抽查约 2%（980 个）并报告超过 96% 的正确性；这不是全量 ground truth。
- 用户研究仅 10 名参与者，平均评分 4.3/5，半数参与者报告节省超过 10 分钟。

## 7. 关键知识点

- “缺失日志下由智能体放宽查询并回溯”在 2026 年已经出现，不能再作为单独 novelty。
- `potential correlation` 是调查假设，若没有来源状态与置信度，不应与实际日志边混为同一证据层。
- 成功找到入口不等于重建了正确完整链，更不等于识别了攻击目标或行为体意图。
- 固定终止类别比自由文本结论更利于 abstention，但仍需独立评价证据充分性和误拒绝。
- 私有日志和生产规则提高现实性，却限制复现、横向比较和错误分析。

## 8. 优点

- 不是纯离线 benchmark，而是在真实生产 SOC 数据库和告警流上运行。
- 明确处理缺失链、无结果查询、分支爆炸和不可调查告警。
- 结构化 SQL 限制比让 LLM 直接阅读全部日志更可控。
- 报告 token、美元、时延和用户节省时间，体现运维约束。
- 由多名分析员标注专项断链集合，优于只用模型自评。

## 9. 局限

- 私有数据、查询模板和生产系统不可公开复现，线上正确性只做小比例抽查。
- 只在日志数据库内回溯，没有独立 PCAP/流量 observation graph 或原始 packet anchor。
- `potential correlation` 未提供概率校准、边级真值或冲突传播。
- 成功率/一致性不是 chain edge、stage、intent 或 claim entailment 指标。
- 通用进程名和模糊 CmdLine 会造成歧义；系统不能自动适应极端噪声。
- 61.8% 的失败与日志留存有关，说明系统受基础数据质量强约束。
- 存在 log injection、混淆和 LLM 被恶意字段影响的风险。
- 摘要与结论对提升幅度分别写为 31.1/63.7 与 34.9/67.5，口径不一致。
- PDF 中仍有占位会议/DOI 元数据，只能按预印本管理。

## 10. 对我选题的启发

- 智能体应后置为 appendix 或联合图查询层，核心创新仍应是可验证的 traffic-log 双源事件图。
- 借鉴查询放宽时，所有新增边必须标记 `candidate`，并保存生成条件、证据来源和拒绝状态。
- 终止机制可扩展为校准的 risk-coverage/abstention：关系不确定或来源冲突时，系统停止生成高层意图。
- 联合图可先通过结构化查询缩小上下文，再让 LLM 输出绑定到节点、边和 raw record 的结论。

## 11. 可转化的研究问题

1. 把查询放宽得到的候选边交给跨源关系校准器，能否降低 SherAgent 式潜在关联的误连接？
2. source conflict 与 relation uncertainty 能否共同决定何时终止链/意图推理？
3. 在相同 token 预算下，联合证据图查询能否比直接日志回溯提高 chain edge recall 与 claim entailment？

## 13. 论文写作可引用句式

- 最新的智能体式安全调查已经能够通过结构化查询放宽和语义分支过滤，在生产日志链断裂时恢复调查入口；但潜在关联仍缺乏跨源边级真值、概率校准与原始流量证据约束。

## 14. 我的批注与疑问

- 摘要和结论提升幅度不一致，后续只能引用绝对表格数值并注明指标定义。
- 线上 53,849 告警不能等价为 53,849 个有完整真值的实验样本。
- “恢复成功”主要看入口是否正确，尚不能证明中间链条没有虚假边。
- 对恶意日志字段和提示注入只做风险讨论，未见系统性红队实验。
