## 已确认的技术方案（基于摘要与说明书概要）

1. 输入：安全告警消息（Security Alert Message）。
2. 任务：判定告警为假阳性（False Positive）或真阳性（True Positive）。
3. 机制：
   - 自动生成告警专属剧本（alert-specific playbook）；
   - 计算初始风险分（Risk Score）；
   - 迭代多阶段收敛过程：LLM 评估告警内容 + 元数据 + 组织上下文；
   - LLM 通过 Agent 模块从组织数据源拉取**追加上下文信息**；
   - 迭代更新风险分直至收敛：低于阈值→丢弃；高于阈值→触发动作；中间→转人工。

## 对 Project05 新主线（B：主动取证规划）的威胁与区分

### 威胁

"置信不足→自动拉取更多数据→循环直到可决策"这个朴素循环机制被覆盖。B 的权利要求**不能**写成"归因置信度不足时由 LLM 请求追加证据并循环"。

### 摘要级可辨的区分点

| 维度 | US12530469 | Project05-B |
|---|---|---|
| 技术问题 | 告警真/假阳性二分类 | 归因粒度多层级判定（technique/intent/campaign/actor/unknown） |
| 循环驱动 | 单一风险分收敛到阈值 | 各候选取证动作的**期望归因粒度增益**估计（证据价值函数）+ 动作序列规划 |
| 状态表示 | 告警内容/元数据/组织上下文 | CTI 侧攻击图与本地证据的**对齐状态**（对齐完整度、缺口类型、冲突） |
| 取数方式 | Agent 拉取组织上下文（无动作选择建模） | 显式动作空间 + 价值排序 + 采集成本约束下的规划 |
| 输出 | 丢弃/触发/转人工 | 粒度门控归因结论 + 最优取证序列 |

### 写法要求

B 的独立权利要求必须把核心限定在：**面向归因粒度层级的证据价值估计模型**与**对齐缺口驱动的取证动作排序/规划**，避免任何"置信度阈值触发追加数据请求"的宽泛表述。
