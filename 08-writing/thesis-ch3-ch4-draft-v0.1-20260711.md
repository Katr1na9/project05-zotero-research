# 第 3 章 问题定义与证据缺口状态

## 3.1 任务设定

APT 调查中，分析师通常同时面对两类信息：一侧是 CTI 报告或攻击知识图谱中描述的行为链，另一侧是主机溯源、网络遥测、进程与文件日志等本地观测。二者往往只能部分对齐。已有工作大量回答“如何抽取 CTI”“如何做图对齐”“如何在闭集上分类 actor”，但较少回答一个更贴近部署的决策问题：当当前证据还不足以支撑目标归因粒度时，系统下一步应获取什么证据、付出多少成本，以及何时必须停止或降级输出。

本文将该决策过程形式化为**对齐之后的成本约束主动取证任务**。系统不重新发明对齐器，也不在证据不足时直接输出更细粒度标签；它接收对齐结果，构造可更新的证据缺口状态，在候选取证动作中选择下一步，并根据执行反馈更新状态，直到达到目标粒度、预算耗尽或判定目标不可达。

形式化地，一次调查 episode 的输入包括：

1. CTI 行为图 \(G=(V,E)\)，节点对应 technique / 行为片段，边对应阶段或依赖关系；部分节点可标记为关键节点。
2. 本地 evidence claims 集合 \(\mathcal{C}\)，每条 claim 带来源指针，并可覆盖一个或多个 CTI 节点（本文实现采用 OR 覆盖语义）。
3. 候选取证动作集合 \(\mathcal{A}\)，每个动作带有公开意图、采集通道与成本；真实可恢复 claim 集合对规划器隐藏。
4. 通道先验与运行时可用性（例如网络遥测可能离线）。
5. 归因粒度序列与目标粒度 \(g^\star\)，以及可选的支持上限 `support_ceiling`。
6. 剩余预算 \(B\)。

系统在每一步输出二者之一：

- 一个非停止取证动作 \(a\in\mathcal{A}\setminus\{\mathrm{STOP}\}\)；或
- 接受当前可支撑粒度的 \(\mathrm{STOP}\)/降级结论，并给出停止原因。

目标不是最大化 actor 分类准确率，而是：在预算内达到 \(g^\star\)；若不可达，则避免越过 `support_ceiling`，并与“应当停止”的判定保持一致。

## 3.2 证据缺口状态

对齐分数或匹配子图本身不足以支撑取证规划。规划器需要的是一个随动作执行而更新的状态 \(s_t\)。本文将 \(s_t\) 定义为对齐感知的**证据缺口状态**，至少包含：

| 分量 | 含义 |
|---|---|
| 已覆盖 CTI 节点 / 边 | 由当前可见 claims 按 OR 覆盖语义诱导 |
| 未匹配节点集合 | 仍构成缺口的 CTI 节点 |
| 关键缺口 | 标记为 critical 且尚未覆盖的节点 |
| 阶段 / 证据类型覆盖 | 供粗粒度规划器使用的摘要统计 |
| 当前可支撑粒度 \(g(s_t)\) | 由覆盖结构与 `support_ceiling` 共同决定 |
| 剩余预算与已执行动作 | 成本约束与重复动作惩罚的基础 |
| 执行反馈摘要 | 例如同类动作的零收益比例 |

其中，可支撑粒度采用由低到高的离散格：

```text
G0_unknown → G1_technique → G2_tactic_intent → G3_campaign
```

实现上，\(g(s_t)\) 由节点覆盖率、边覆盖率、阶段多样性和关键节点覆盖共同决定，并被 `support_ceiling` 截断。该规则是可审计的结构启发式，不是对真实分析师判断的完整建模；其作用是把“现在最多能说到哪一层”变成规划器可读取的状态分量。

状态更新遵循闭环：

```text
对齐结果 / 初始可见 claims
  → 构造 s_t
  → 选择动作 a_t（或 STOP）
  → 环境按通道可用性返回实际恢复的 claims
  → 更新可见集合与 s_{t+1}
  → 重算 g(s_{t+1})
```

因此，对齐不再是流水线终点，而是规划状态的输入。

## 3.3 动作空间与信息边界

### 3.3.1 取证动作

候选动作对应安全调查中的证据获取操作，而非“向语言模型追问更多信息”。典型动作包括：扩展日志窗口、拉取主机溯源子图、查询网络会话摘要、审查良性/噪声进程、以及显式停止。每个非停止动作在数据层至少包含：

- 公开字段：`intended_cti_node_ids`、`acquisition_channel`、`cost`、自然语言请求，以及可选的手写 `expected_*` 摘要；
- 隐藏字段：`recoverable_claim_ids`，仅供环境模拟与 Oracle 使用。

公开意图表示“该请求希望解决哪些 CTI 缺口”，必须能从调查问题与 CTI 图推导，而不能从隐藏恢复集合反推。

### 3.3.2 `intended ≠ OR(recoverable)` 信息边界

若公开意图恰好等于隐藏可恢复 claim 的 OR 覆盖节点集，则在通道在线时，节点级兼容性评分会退化为读取答案键。为此，本文施加编译时硬约束：对每个非 STOP、非空噪声动作，

```text
intended  ≠  OR-cover(recoverable_claim_ids)
```

允许的合法不对齐包括过宽意图、过窄意图，以及空意图的良性审查。完整解耦还需要运行时通道门控：通道离线时，声明目标不等于实际恢复，执行后才暴露零收益反馈。二者缺一不可——只做通道门控，不足以消除通道在线时的泄题。

### 3.3.3 显式 STOP

\(\mathrm{STOP}\) 是零成本公共动作：结束取证并接受当前可支撑粒度。它把“继续还是认输”纳入同一动作空间，使过早停止、正当降级与预算耗尽可以在同一协议下计量。

## 3.4 决策目标与评价接口

设 Oracle 在已知通道实现下的最小达标成本为 \(C^\star\)。规划器的核心评价不是单步分类准确率，而是 episode 级指标：

- **success**：是否在预算内达到目标粒度；
- **cost-to-target**：仅对成功 episode 的累计成本；
- **regret**：相对 \(C^\star\) 的额外成本；
- **ceiling violation**：是否输出超过 `support_ceiling` 的粒度；
- **premature / justified stop**：相对 Oracle 可达性的停止质量；
- **zero-yield**：执行后无新 claim 的动作次数。

该接口把方法章节与后续实验章节对齐：第 4 章给出在信息边界下可读状态、可选动作的规划器；第 5–6 章用开发矩阵、压力测试与异构真留出检验其可复现性与成本行为。

## 3.5 本章边界

本章定义的是决策问题，而不是新的 CTI 抽取器、provenance 对齐器或 actor 分类器。LLM 若出现，只作为可选的离线语义编译/解释接口，不进入在线动作选择。学习型规划器（Logistic、XGBoost，以及条件具备后的 DQN）被视为同一问题设定下的策略族，其是否进入论文核心取决于后续 Gate，而不是本章的默认承诺。

# 第 4 章 对齐感知主动取证规划方法

## 4.1 方法总览

第 3 章把问题收束为“状态 → 动作 → 反馈 → 更新”。本章给出该闭环的可实现实例，模块如下：

```text
异构证据
  →（可选）语义编译为 evidence claims
  → 证据缺口状态 s_t
  → 动作–缺口兼容性 / 成本敏感打分
  → 选择 a_t 或 STOP
  → 通道门控执行
  → 状态与粒度更新
```

当前工程主线中，**可部署规则基线是 M2**；**M3a** 是检验“节点级 action–gap 兼容性是否足以改善规划”的机制变体；Logistic M3b 与 XGBoost 是已实现的学习对照；DQN/Dueling DQN 仅在非短视诊断与环境多样性 Gate 通过后进入。LLM 不在主循环内。

## 4.2 语义编译接口（可选、离线）

异构 CTI 文本、IOC、日志摘要与 provenance 片段需要先进入统一的 evidence claim schema，才能参与覆盖计算。本文将该步骤定义为**受 schema 约束的语义编译接口**：输入是带来源的原始材料，输出是可回指事件/文件的 claims。

该接口可以人工完成，也可以由离线 LLM 辅助草拟，但必须满足：

1. 输出符合 claim schema，并保留来源指针；
2. 不得把隐藏 `recoverable_claim_ids` 提供给意图标注模型；
3. 编译质量需独立评估后，才能讨论其对冻结规划器的下游影响。

在已完成的主实验中，真留出案例的 claims 由可审计编译脚本与人工规范生成，**主循环未调用 LLM**。因此，方法贡献不依赖在线语言模型。

## 4.3 规则规划器 M2：成本、重叠与执行反馈

### 动机

在没有可靠单步监督时，最稳妥的可部署起点是利用公开的期望效果摘要、阶段/证据类型缺口、动作重叠与历史零收益反馈做短视打分。M2 不读取隐藏恢复集合，适合作为信息边界下的强规则基线。

### 机制

对候选动作 \(a\)，M2 综合以下公开信号（实现见 `run_mvp.py` 中 `m2_action_score`）：

- 手写期望效果：粒度提升、不确定性下降、过度归因风险下降；
- 阶段缺口与证据类型缺口；
- 与已执行动作的签名重叠惩罚；
- 同类动作历史零收益比例；
- 相对剩余预算的成本比。

每步选择得分最高的可用动作；若 \(\mathrm{STOP}\) 更优或无正收益动作，则停止。

### 角色

后续实验表明，在 C07–C09 冻结 holdout 与紧预算曲线上，M2 是当前最强可部署规则基线。方法章节将其定位为**对照与部署锚点**，而不是被 M3a 默认取代的过渡物。

## 4.4 机制变体 M3a：action–gap 兼容性

### 动机

M2 依赖阶段/类型级摘要与手写 `expected_*`。若关键失败来自“动作公开意图与当前未匹配 CTI 节点对不齐”，则需要更细的节点级兼容性。M3a 检验的假设是：仅用公开的 `intended_cti_node_ids` 与当前未匹配集合，即可在成本约束下改善选路。

### 机制

令 \(\mathcal{I}(a)\) 为动作公开意图节点，\(U(s_t)\) 为当前未匹配节点，\(K\) 为关键节点集合。若 \(a=\mathrm{STOP}\)，得分为 0（break-even）。否则

\[
\begin{aligned}
T &= \mathcal{I}(a)\cap U(s_t),\\
\mathrm{score}_{\mathrm{M3a}}(a,s_t)
&= \frac{8|T\cap K| + 3|T| + 2\cdot\mathrm{prec} + \mathrm{rec} - 0.5\cdot c(a)}{c(a)},
\end{aligned}
\]

其中 \(\mathrm{prec}=|T|/|\mathcal{I}(a)|\)，\(\mathrm{rec}=|T|/|U(s_t)|\)，\(c(a)\) 为成本。该分数**不读** `recoverable_claim_ids`，也**不读**通道可靠性先验。

### 边界

M3a 是可证伪机制变体。开发矩阵上它曾相对 M2 提高成功率；在信息边界收紧（intended≠OR）后成本上升；在三条异构真留出上与 M2 同样 45/45 达标，但平均成本更高。因此，正文不得把 M3a 写成“已证明的成本最优规划器”，而应写成“节点级兼容性假设的可复现检验对象”。

## 4.5 学习型对照：Logistic M3b 与 XGBoost

在同一状态–动作特征上，本文实现两类学习对照：

1. **Logistic M3b**：学习条件效用 / 到达概率等，并曾尝试执行反馈自适应；在当前协议下未稳定超越强规则选路，故冻结为近负对照。
2. **XGBoost action-value**：以树模型预测 state–action 价值，训练仅使用开发案例，测试使用参数锁定 holdout。相对 Logistic，它修复了部分失败条件并小幅降低平均成功成本，但仍未超过 M2；主标签 AUROC 亦未稳定优于 Logistic。

二者说明：把规划写成监督学习问题是可行的，但**现有特征与数据规模尚未证明学习器应取代 M2**。DQN 等非短视方法需要额外 Gate：必须先构造“单步最优 ≠ 长期最优”的诊断环境，并补足可辩护的训练环境多样性，而不是把同一案例的 mask/seed 夸大为独立环境。

## 4.6 通道可靠性门控与状态更新

### 通道门控

每个动作绑定 `acquisition_channel`。运行时若通道离线，则实际恢复集合为空或退化，即使公开意图非空。规划器只在执行后通过反馈看到零收益，而不能在选动作前读取隐藏实现。可靠回退动作应落在其他通道上，使“网络不可用时改走主机取证”成为可检验行为。

### 状态与粒度更新

动作返回的新 claims 并入可见集合后，系统重算节点/边覆盖、未匹配集合、关键缺口与 \(g(s_{t+1})\)。若 \(g(s_{t+1})\ge g^\star\)，episode 成功结束；若预算耗尽或仅剩非正收益动作，则 STOP/降级；若结构上不可达，则应与 Oracle 的正当降级对齐。`support_ceiling` 保证系统不会因为局部覆盖波动而越级输出。

## 4.7 显式停止与降级语义

停止不是事后分析，而是动作空间中的一等公民。本文区分：

- **目标达成停止**：已达 \(g^\star\)；
- **正当降级停止**：Oracle 亦不可达，接受低于目标的可支撑粒度；
- **过早停止**：Oracle 仍可达时结束；
- **预算耗尽**：无剩余成本继续取证。

该语义使 M4 压力测试能够分开检验“会不会停”与“会不会选路”：真正不可达时强方法可对齐正当降级；部分可达但预算紧时，仅会停止并不足以保证选对回退路径。

## 4.8 实现边界与可审计输出

实现上，主循环是确定性的状态构造与打分选择，核心逻辑集中在实验脚本与案例 schema。每次决策应能导出：

- 当前覆盖与缺口摘要；
- 候选动作的公开意图、通道与成本；
- 选中动作及得分依据；
- 执行后新恢复的 claim 与来源指针；
- 更新后的可支撑粒度与停止原因。

不在本章承诺的内容包括：在线 LLM 效用预测、自由 actor 裁决、未通过 Gate 的 DQN 主模型，以及“M3a 已在 holdout 上成本优于 M2”。这些边界与第 6 章结果、第 7 章讨论直接对应，避免方法叙述与证据脱节。

## 4.9 本章小结

第 4 章给出了对齐感知主动取证的可实现闭环：可选语义编译、证据缺口状态、M2/M3a 规则规划、学习对照、通道门控、状态更新与显式 STOP。方法上的可辩护主张是——把部分对齐转化为可更新状态，并在信息边界下做成本约束决策；经验上的强弱比较留给第 5–6 章，且必须如实报告 M3a 的成本负结果与学习器尚未超越 M2 的事实。
