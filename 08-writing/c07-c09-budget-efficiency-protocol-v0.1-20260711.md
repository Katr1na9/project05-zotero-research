# C07-C09 冻结预算效率实验协议 v0.1

日期：2026-07-11  
状态：预注册，结果生成前冻结

## 1. 研究问题

在证据遮蔽条件、采集通道状态和目标归因粒度相同的情况下，Project05 的规划器能否在接近 Oracle 最小可达成本的紧预算区间内，以更低代价达到 `G3_campaign`？

本实验只评估已经冻结的确定性规划器，不评估 LLM，也不允许依据 C07-C09 结果修改 M3a 权重。

## 2. 实验单位与配对设计

- 独立案例：C07、C08、C09，共 3 个真实攻击案例。
- 配对区组：`(case_id, mask_strategy, mask_intensity, seed)`。
- 遮蔽策略：random、stage、discriminative。
- 遮蔽强度：0.2、0.4、0.6。
- 随机种子：11、23、37、41、53。
- 每个案例 45 个重复条件，共 135 个配对条件。
- 同一区组内，所有规划器和预算档位共享相同的隐藏证据集合及确定性通道状态。

重复遮蔽条件用于评估条件敏感性，不作为新增独立攻击案例。

## 3. 冻结方法

- `coverage_greedy`
- `cmi_proxy`
- `project05_m1`
- `project05_m2`
- `project05_m3a_gap_compat`
- `oracle_optimal`，只作为评测下界，不是可部署方法

M3a 继续使用 `run_mvp.py` 中已冻结的 gap-compatibility 公式与权重，不进行 holdout 调参。

## 4. 预算构造

对每个配对区组，先在原始案例预算内运行 Oracle，得到最小可达成本 `C*`。随后评估：

1. `C*`
2. `min(C* + 1, 原始预算)`
3. `min(C* + 2, 原始预算)`
4. 原始预算

重复预算档位去重。若 Oracle 在原始预算内不可达，则只保留原始预算，并将该条件标记为 Oracle 不可达，不进入以 `C*` 为横轴的主曲线。

## 5. 主要指标

- `success_rate`：在给定 Oracle 相对预算下达到目标粒度的比例。
- `mean_cost_to_target_on_success`：仅在成功条件上的平均目标到达成本。
- `premature_stop_rate`：Oracle 可达但规划器提前停止且未达到目标的比例。
- `ceiling_violation_rate`：输出超过证据支持上限的比例。
- `condition_count`：每个曲线点实际覆盖的配对条件数，防止预算去重后误读样本量。

## 6. 解释规则

- 若 M3a 在 `C*` 或 `C*+1` 上稳定优于 M2/CMI，并且没有增加 ceiling violation，则可主张 gap-compatibility 对紧预算规划有增益。
- 若 M3a 只在个别案例或个别遮蔽条件获益，则只报告条件性优势，不作总体优越性主张。
- 若 M3a 与 M2 持平或更差，则论文主贡献收束到证据状态表示、信息边界、Oracle 相对评测协议和真实数据验证；不把 M3a 写成性能创新。
- C07-C09 结果不得反向用于修改方法参数。任何后续新方法必须使用新的开发案例，并再次在未见案例上验证。

## 7. LLM 边界

本实验没有 LLM checkpoint、API 调用或 LLM 生成字段。证据 claim、CTI 节点和采集动作均来自规则编译与人工复核；M1/M2/M3a 均为确定性算法。因此本实验不能证明 LLM 有效，也不能把 LLM 写入该实验的因果贡献。
