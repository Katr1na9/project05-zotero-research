# Project05 非短视必要性与 DQN 必要性两级 Gate 协议 v0.1

日期：2026-07-11
状态：已按冻结协议完成
角色：廉价诊断，不替代论文/专利主线

## 1. 问题

本实验分开回答两个问题：

1. **非短视规划是否必要**：是否稳定存在“当前收益最高的动作会消耗关键预算，而先执行低即时收益的解锁动作才能达到目标”的状态？
2. **DQN 是否必要**：即使非短视规划必要，Depth-2 或精确动态规划是否已经足够且计算便宜？

“非短视必要”不自动推出“强化学习必要”。

## 2. 参数化环境

每个环境包含：

- `distractor_i`：成本为 1，提供即时局部收益，但不解决关键归因目标；
- `setup_1 ... setup_d`：成本为 1，即时收益为 0，按顺序解锁后续动作；
- `payoff`：成本为 1，仅在全部 setup 成功后可执行，成功则达到目标粒度；
- `STOP`：成本为 0，接受当前未达标状态。

预算为 `d + 1 + slack`。当 `slack=0` 时，先执行任何 distractor 都会使目标不可达；当 `slack=1` 时，允许一次局部探索后仍有机会完成解锁链。

冻结网格：

| 参数 | 取值 |
|---|---|
| 解锁深度 `d` | `1, 2, 3, 4` |
| 预算余量 `slack` | `0, 1` |
| distractor 数量 | `1, 3, 6, 10` |
| distractor 即时收益 | `0.5, 1.0, 2.0` |
| setup/payoff 可靠性 | `1.0, 0.8` |
| 重复 seed | `11, 23, 37, 41, 53, 67, 79, 83, 97, 101` |

共 `192` 个独立参数环境；每个环境 10 个重复随机实现。独立样本数是 192，不是 episode 总数。

## 3. 策略

| 策略 | 作用 |
|---|---|
| `one_step_gain_cost` | 只看即时收益/成本的短视基线 |
| `project05_m2` | 直接复用 `run_mvp.py` 的冻结 M2 公开动作评分；不读取隐藏转移 |
| `depth2_m2` | 先最大化两步内目标到达概率；两步都看不到目标时回退冻结 M2 |
| `dp_oracle` | 在已知环境模型上计算全深度最大目标到达概率，并以期望成本打破平局 |

XGBoost 不作为本 Gate 的主比较：它在 C01–C06 上训练，直接迁移到人工 MDP 是分布外输入，无法区分“规划不足”和“表示分布漂移”。本 Gate 只诊断规划深度。

## 4. 共同目标与信息边界

- 主目标：episode 是否在预算内达到目标。
- 次目标：成本、动作数、premature STOP、首动作、规划状态展开数和规划耗时。
- 所有非 Oracle 策略只读取公开成本、即时 expected effects、先决条件是否满足、剩余预算和实际反馈。
- `dp_oracle` 读取完整转移模型，仅作规划上界，不作为可部署方法。
- 同一 `(scenario, seed)` 的随机动作结果由哈希固定，所有策略共享同一实现。

## 5. 两级 Gate 判据

### Gate A：非短视必要性

同时满足以下条件才通过：

1. 至少 24 个独立环境中 `dp_oracle` 可达；
2. 在可达环境上，`dp_oracle` 相对冻结 M2 的 success 优势至少 `0.20`；
3. Depth-2 在 `d=1` 子集上相对 M2 有正修复，证明增益来自前瞻而不是随机 tie-break；
4. 结果覆盖至少两个不同 distractor 数量和两个不同即时收益水平。

该 Gate 只证明所定义主动取证环境族中存在稳定非短视冲突，不估计真实世界发生率。

### Gate B：DQN 必要性

只有同时满足以下条件才批准 DQN/Dueling DQN：

1. `dp_oracle - depth2_m2` success 差至少 `0.10`；
2. 精确 DP 的 p95 单次决策耗时超过 `100 ms`，或最大状态展开数超过 `100,000`；
3. 性能差覆盖至少两个解锁深度，而非单个手工极端点。

若 Depth-2 不足但 DP 仍很便宜，结论是“需要更深规划，但当前不需要 DQN”。

## 6. 预登记解释

| 结果 | 决策 |
|---|---|
| Gate A 不通过 | 关闭 RL 主线；非短视仅列限制 |
| Gate A 通过、Gate B 不通过 | 使用轻量前瞻/DP；DQN 降为未来工作或附录 |
| Gate A、B 均通过 | 才实现 DQN/Dueling DQN，并冻结 reward、STOP 与离线评价协议 |

禁止根据结果修改网格或阈值后再把同一批输出称为预登记结果。
