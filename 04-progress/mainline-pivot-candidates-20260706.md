## 2. 候选强主线

### 候选 A：CTI 侧攻击图与本地流量/溯源证据的可验证对齐与语义提升

一句话：把"报告里说的攻击"和"自己网络里观测到的行为"在图层面对齐起来，让归因结论落在可验证的本地证据上。

- 核心技术问题：CTI 文本侧攻击行为图（AttacKG+/EXTRACTOR 产物）与本地流量/日志侧证据图（attack summary graph、InfoPath、流量会话图）之间的**跨源图对齐（cross-source graph alignment）**与**语义提升（semantic elevation）**——把匿名的本地异常节点/路径提升为带 ATT&CK/意图语义、可回指报告证据的归因证据链。
- 技术核心（实质算法贡献，不是控制层）：
  1. 两侧证据图的统一序列化与嵌入表示；
  2. 图匹配/子图检索算法（结构 + 语义混合相似度）；
  3. 对齐置信度与冲突检测；
  4. 对齐结果驱动的意图/campaign 级结论生成。
- 独特资产：**Project03 的 CENI 真实平台**（多模态流量探针、在线检测、Neo4j 威胁图谱 13.6 万节点）可以产生真实流量侧证据，公开侧可用 DARPA TC/OpTC。硕士论文有真实系统支撑，答辩强度高，且与课题组现有工作天然衔接。
- 与红线的边界：
  - SHIELD 红线覆盖的是"provenance graph + LLM 攻击摘要"，不覆盖跨源对齐；
  - CTIConnect 明确留下"未纳入 provenance graph"的缺口（已入复利日志）；
  - `novelty-checks.md` 缺口 3"CTI text graph 与 audit-log provenance graph 的可验证对齐"当时标记为"暂时保留"，至今未被撞掉。
- 主要风险：
  - TAA-EPLMR 全文未得，evidence path 表述需避让；
  - 实现复杂度是四个候选里最高的，需要在实验设计时收窄为小规模 case study + 公开数据集复现；
  - EXTRACTOR 本身就说自己的图"可作为 threat hunting query graph"，必须把创新落在**对齐算法与对齐后的语义提升**，不能停留在"拿 A 的图去 B 里查"。

### 候选 B：面向归因粒度提升的证据价值建模与主动取证规划

一句话：不只说"证据不够"，而是建模"哪条证据对提升归因粒度价值最大"，把取证变成一个可学习的规划问题。

- 核心技术问题：给定当前证据状态与候选归因假设，估计每个候选取证动作（拉取某类日志、请求样本、查基础设施历史）的**期望归因增益**，输出最优取证序列。形式化为证据状态空间上的序贯决策（expected information gain / bandit / 启发式规划均可作为实例化）。
- 技术核心：可学习的证据价值函数 + 取证规划器。已有的充分性画像/粒度门控全部复用为"状态表示"和"环境反馈"，原有积累利用率最高。
- 与红线的边界：
  - 学术侧初步检索未见直接同题工作（见 1.1）；
  - **但新发现 US12530469 是直接专利威胁**（见 1.2），写法必须避开"置信度阈值触发追加数据请求循环"，改为限定在"面向归因粒度层级的证据价值估计模型 + 取证动作排序"这类更具体的技术手段；权利要求原文补读已按用户决策从当前 workflow 剔除。
- 评测方式：evidence ablation benchmark 反向构造——从完整案例出发遮蔽证据，考察规划器能否以最短取证序列恢复最高归因粒度，对比 random / 固定顺序 / 贪心启发式。
- 主要风险：
  - 评测基于构造场景，可能被质疑"仿真味重"；
  - 专利空间因 US12530469 变窄，但当前仅保留摘要级红线，不再将其权利要求全文核查作为阻塞项；
  - 若证据价值函数退化为规则打分，贡献又会滑回"控制层"。

### 候选 C：交互式 APT 调查 agent（不推荐）

本轮检索确认 ExCyTIn-Bench、CyberSleuth、AutoBnB-RAG、Multi-Agent Incident Response、AIR 等已密集覆盖"LLM agent 做安全调查/取证"。除非做出 benchmark 级贡献，否则不建议作为主线。**判定：排除。**

### 候选 D：多模态 CTI 证据语义编译（不推荐单独成题）

LLM 把异构输入编译为带类型的证据主张图。与 AttacKG+/TTPrint（evidence-grounded TTP extraction）距离过近，单独成题风险高。**判定：只作为 A/B 的输入模块。**

## 3. 推荐组合

推荐：**A 为论文主线，B 为第二贡献模块**。

理由：

1. A 有实质算法核心（图对齐 + 语义提升），有真实平台（Project03/CENI）支撑，是四个候选中"硕士论文答辩强度"最高的；
2. B 骑在 A 的对齐证据之上（对齐失败/证据缺口 → 触发取证规划），二者天然衔接成"对齐—评估—补证"闭环，闭环可以在 CENI 平台上做真实演示（探针部署、流量窗口采集、Neo4j 查询都是真实可执行的取证动作）；
3. 原有充分性/门控/拒答积累全部复用为第 3 章问题定义和实验评价维度，前期工作不浪费；
4. 专利可以从 A+B 闭环里切"跨源证据对齐驱动的取证规划"这类窄口，避开 US12530469 的告警调查循环和 US12368730 的多证据归因。
