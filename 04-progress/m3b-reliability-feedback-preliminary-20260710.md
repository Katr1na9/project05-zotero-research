# M3b-3 可靠性反馈：预备结果与信息边界（2026-07-10）

## 已实现内容

- 按 `action_type + expected_evidence_types` 建立 `Beta(1,1)` 动作组可靠性后验。
- 有有效产出时增加 alpha，零产出时增加 beta。
- 自适应策略评分为：

```text
P(补上关键缺口) × 可靠性后验均值 - 0.1 × 动作成本
```

- 每个 action trace 记录动作组、执行前后的可靠性、M3b 预测概率与校正后效用。
- 正常动作空间、静态 M3b、M2、M3a、coverage-greedy 与 Oracle 完成 matched-episode 对比。
- 重复诱饵压力测试为每个关键缺口动作加入两个零产出 twin。

## 正常动作空间

自适应 M3b 与静态 M3b、M3a、Oracle 一致：成功率 `1.0000`，平均达标成本 `1.6519`。这是预期现象，因为正常动作空间中没有反馈驱动的可靠性差异。

## 重复同质 twin 诱饵结果

| Planner | 成功率 | 平均达标成本 | 平均预算使用 |
|---|---:|---:|---:|
| 自适应 M3b | 0.7852 | 2.5849 | 3.5704 |
| 静态 M3b | 0.9037 | 3.1311 | 3.6000 |
| M3a | 0.9037 | 3.1311 | 3.6000 |
| M2 | 0.8370 | 1.7876 | 2.6370 |
| Oracle | 1.0000 | 1.6519 | 1.6519 |

自适应策略降低了一部分成功 episode 的成本，但总体成功率下降，不能据此宣称效果改善。

## trace 复核

一个 C04 条件的动作序列为：

```text
zz_decoy_02_C04-AA-002: reliability 0.50 -> 0.33, yield=0
zz_decoy_01_C04-AA-002: reliability 0.33 -> 0.25, yield=0
C04-AA-002:            reliability 0.25 -> 0.40, yield=2
```

三个动作的公开分组均为 `recover_network_summary|network_summary`。因此第一次失败后，后验无法区分“同组的坏 twin”与“同组的真实动作”，会同时降低两者的分数。

## 结论

完全同质 twin 是一个合理的信息边界负对照：在动作执行前和动作分组层面都没有区分真伪的公开变量时，任何组级可靠性后验都不应被期待识别真动作。

它不是检验可靠性反馈收益的合适正向测试。下一轮实验应单列“公开可区分的数据源/采集通道故障”场景：动作携带公开的采集通道标识，多个零产出动作共享故障通道，而可达目标的替代动作位于另一通道。此时策略第一次失败后可合理降低故障通道的后验，并转向替代通道。
